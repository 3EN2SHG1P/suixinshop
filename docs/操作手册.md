# 操作手册

> 面向**已经把项目跑起来**的人。还没跑通先看 [README.md 第 2 节](../README.md#2-5-分钟跑起来)。
> 本手册按「我要做一件事」组织，不按页面罗列。页面全清单见 [功能清单.md](./功能清单.md)。

### 0. 开始之前

两个地址、两个终端：

| 入口 | 地址 | 起法 |
|---|---|---|
| 后台管理 + 接口 | <http://127.0.0.1:8001> | `cd backend` → `uv run python run.py` |
| 商城前台 | <http://127.0.0.1:8000/> | `cd front` → `python -m http.server 8000` |

| 账号 | 密码 |
|---|---|
| 后台 `admin` | `seed base` 首次运行打印的随机密码；忘了看 [#9](#9-忘记后台密码) 重置 |
| 前台会员 `10000000001` / `2` / `3` | `123456` |

> `operator` 只是 base 数据里的演示角色，**没有建对应账号**。
>
> 需要多账号演示，在「权限管理 → 管理员」里自行新增并分配角色（见 [#6](#6-加一个管理员只给他商品权限)）。

### 1. 登录 / 退出

1. 打开 <http://127.0.0.1:8001>，根路径自动跳登录页
2. `admin` + 上面的密码 → 进入仪表盘
3. 退出：点顶栏右侧用户区域展开下拉 → 「退出登录」

未登录直接访问后台任意子页会被弹回登录页，这是正常拦截。

### 2. 上架一个商品

后台 → 商品管理 → 商品列表 → 新增。

1. 基本信息：商品名称、分类（必选）、品牌、单位
2. 价格库存：销售价、市场价、库存
3. 规格 SKU：加了规格（如颜色 / 尺码）就要给每个组合设价格与库存；**不设 SKU 前台无法加购**
4. 图片：主图至少一张
5. 保存后回到列表，把状态置为「上架」

验证：前台 <http://127.0.0.1:8000/> 能搜到该商品，详情页选规格后能加购。

> 若 `.env` 的 `GOODS_AUDIT_ENABLED=true`，新商品需审核通过才上架，审核入口在商品列表的审核操作。

### 3. 处理一笔订单（发货）

后台 → 订单管理 → 订单列表。

1. 按状态筛「待发货」
2. 打开订单详情抽屉，核对收货信息与商品明细
3. 点「发货」：选快递公司 + 填快递单号 → 确认
4. 多笔同状态订单可用「批量发货」

订单状态流转：待付款 → 待发货 → 已发货 → 已完成；待付款超过 14 分钟（`ORDER_PAY_TIMEOUT_MINUTES`）会被关闭。改价、取消都在详情抽屉里。

> 关单是**惰性判定**：会员打开订单详情 / 点支付 / 查支付状态时才会把超时订单置为已取消，后台列表不会主动触发，系统内也没有定时任务。后台看到的「待付款」可能已超时，需要批量关单请自行加定时任务（见 [已知限制](../README.md#7-已知限制)）。

快递公司没有想要的，先去 订单管理 → 物流公司 里新增。

### 4. 审核售后

前台会员在「我的订单 → 申请售后」提交后，后台 → 订单管理 → 售后管理。

1. 状态筛「待审核」
2. 同意 / 拒绝，填写处理说明
3. 退货退款类：等会员在「售后中心」填退货运单 → 后台点「确认收货」

注意：同意退款只推进售后单状态，**不发起真实退款、不回退优惠券与积分**（演示项目限制）。

### 5. 配一张优惠券

后台 → 营销中心 → 优惠券 → 新增。

1. 类型：满减 / 折扣；填面额或折扣率
2. 使用门槛（满 X 元可用）、有效期、发放总量、每人限领
3. 保存并启用

验证：前台 → 我的优惠券 → 领券中心领取 → 结算页可选到该券并抵扣。

> 每人限领填大于 1 不生效（库表有唯一约束，见 [已知限制](../README.md#7-已知限制)）。

### 6. 加一个管理员，只给他商品权限

1. 权限管理 → 角色 → 新增：填角色名与标识（如 `goods_operator`）
2. 在权限树里只勾「商品管理」相关的菜单 / 按钮 / 接口
3. 权限管理 → 管理员 → 新增：账号、姓名、密码，绑定刚建的角色
4. 用新账号登录：左侧只见商品菜单，无权限的接口请求会被后端拦截

要点：

<span>&nbsp;•&nbsp;&nbsp;&nbsp;</span>**写操作仅限超管**：角色与权限资源只有超管能改（`data_scope=3`），普通管理员改不了角色

<span>&nbsp;•&nbsp;&nbsp;&nbsp;</span>**生效延迟**：改完权限最长 5 分钟后生效（权限缓存 300 秒），要立刻生效就让该账号重新登录

<span>&nbsp;•&nbsp;&nbsp;&nbsp;</span>**数据权限范围**：`data_scope` 只在商品模块与管理员账号生效，订单 / 会员 / 营销只做功能级鉴权

<span>&nbsp;•&nbsp;&nbsp;&nbsp;</span>**先复制再减法**：角色可以「复制」一个再改，比从零勾选快

### 7. 前台走一单（演示闭环）

0. 前台登录 / 注册页：<http://127.0.0.1:8000/login.html>、<http://127.0.0.1:8000/register.html>（无 `/front/` 前缀）
1. 打开 <http://127.0.0.1:8000/>，挑商品 → 选规格 → 加入购物车
2. 购物车勾选 → 去结算（未登录会先登录；游客购物车登录后自动合并）
3. 填 / 选收货地址 → 领券 → 提交订单
4. 收银台选支付方式 → 模拟扫码支付 → 确认支付
5. 「我的订单」看到该单；回后台订单列表也能查到同一笔

支付是模拟的，不接真实网关、不扣真钱。

### 8. 重置数据

在 `backend/` 执行，全部幂等：

| 目的 | 命令 |
|---|---|
| 只清演示数据（商品 / 订单 / 会员等） | `uv run python -m seed.runner clean-demo` |
| 只清基础数据（管理员 / 角色 / 权限） | `uv run python -m seed.runner clean-base` |
| 重新灌演示数据 | `clean-demo` → `demo` |
| 还原到全新初始状态 | `clean-demo` → `clean-base` → `base` → `demo` |

### 9. 忘记后台密码

1. `.env` 里加一行 `ADMIN_INIT_PASSWORD=你的新密码`
2. 重跑 `uv run python -m seed.runner base`（会按该值覆盖 admin 密码）
3. 登录后把这一行删掉或留空

彻底重置：`clean-base` → `base`（会清空管理员 / 角色 / 权限，然后重新打印随机密码）。

### 10. 常见问题

| 问题 | 处理 |
|---|---|
| `127.0.0.1:8001` 打不开或 404 | 确认在 `backend/` 执行了 `run.py`；登录入口就是根路径，接口文档在 `/api/docs` |
| `127.0.0.1:8000` 打不开 | 前台要单独起静态服务，且访问根路径，没有 `/front/` 前缀 |
| 登录提示账号或密码错误 | 翻回 `seed base` 首次运行的终端输出；或用 [#9](#9-忘记后台密码) 覆盖密码 |
| 点退出没反应 | 先展开顶栏右侧用户下拉，再点「退出登录」 |
| 提示数据库连接失败 | MySQL 没起，或 `.env` 的 `DB_*` 不对；库不用手工建，`seed base` 会自动创建 |
| 前台有页面但没商品 | 只跑了 `base`，补跑 `seed demo` |
| 改了 `.env` 不生效 | 重启后端（`Ctrl+C` 后重新 `run.py`） |

更多启动期报错见 [README.md 的「跑不起来怎么办」](../README.md#5-跑不起来怎么办)。
