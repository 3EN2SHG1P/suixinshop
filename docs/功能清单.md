**状态怎么读**：

<span>&nbsp;•&nbsp;&nbsp;&nbsp;</span>**● 完整**：接口有自动化测试覆盖，且业务链路闭合（改动会连带影响其它模块）。

<span>&nbsp;•&nbsp;&nbsp;&nbsp;</span>**◐ 部分**：页面与接口可用，但存在两类缺口之一——**链路未闭合**（售后只推进状态不真实退款、物流只存单号无轨迹、秒杀库存与限购未接入、运费模板不参与实付），或**只有前台链路被测、后台 CRUD 无测试**（优惠券、广告、公告）。逐条缺口见 [§4 规划中](#4-规划中尚未实现)。

<span>&nbsp;•&nbsp;&nbsp;&nbsp;</span>**○ 仅 CRUD**：页面与接口齐全，但**没有自动化测试覆盖**（`routers/content.py`、`routers/marketing.py`、`routers/admin_logs.py` 在测试中零命中），拿去做二次开发时要自己补回归用例。

前台 18 页不单列状态：整体走 `tests/test_shop.py` 的「预览 → 下单 → 支付 → 售后」全链路断言，唯一演示实现是收银台（模拟支付）。

**权限模型**分四级：菜单（页面入口）、按钮（页面内操作）、接口（URL + 方法）、数据（`data_scope`）。

`data_scope` 取 1 仅本人 / 2 本部门及子部门 / 3 全部，多角色取最大值。角色与权限资源的写操作仅限超管。

### 2. 商城前台（18 页，8000 端口）

完整购物闭环，全部接 `/api/v1/shop/*` 真实接口，与后台同库联动。

| 页面 | 能干什么 |
|---|---|
| `index` | 首页：轮播、分类导航（父分类展开子面板、叶子进列表）、公告、楼层商品 |
| `search` | 搜索列表：关键词 / 分类 / 品牌 / 价格筛选、排序、分页 |
| `detail` | 详情：多规格 SKU 联动、加购、立即购买、评价、售后保障 |
| `add-to-cart` | 加购成功快照 + 猜你喜欢 |
| `cart` | 购物车：改数量、勾选、删除、结算（游客本地 / 会员服务端两态，登录自动合并） |
| `checkout` | 结算：服务端 preview 算钱、优惠券与积分抵扣、提交订单 |
| `address` / `address-add` / `address-edit` | 收货地址列表（选择 / 管理两态）、新增、修改（省市区三级级联） |
| `payment` / `wechat-pay` | 收银台（支付方式、倒计时）、模拟扫码支付（轮询 + 确认） |
| `orders` | 我的订单：状态 Tab、取消 / 确认收货 / 查物流 / 再次购买 / 申请售后 / 评价 |
| `after-sale` | 售后中心：四状态 Tab、申请（仅退款 / 退货退款）、撤销、填退货运单 |
| `coupons` | 我的优惠券：未使用 / 已使用 / 已过期 + 领券中心 |
| `points` | 我的积分：余额 / 等级折扣 / 流水 |
| `login` / `register` | 手机验证码登录注册（随机生成、5 分钟有效、错 5 次作废；`SMS_MOCK=true` 时验证码直接显示在页面上） |
| `service` | 服务中心：自助入口 6 项 + FAQ，免登录 |

### 3. 业务口径速查

| 事情 | 现在的规则 |
|---|---|
| 库存扣减 | SKU 级单语句条件扣减 `UPDATE ... WHERE stock >= N`，不足即失败，不会卖成负数 |
| 结算凭据 | `previewToken` 一次性，15 分钟有效，存在进程内存 |
| 待付款超时 | 默认 14 分钟（`ORDER_PAY_TIMEOUT_MINUTES`）；**惰性关单**——会员访问订单详情 / 支付 / 查状态时才判定，无定时任务，后台列表不会主动关单 |
| 金额计算 | 统一走 `core/money.py`，`Decimal` + `ROUND_HALF_UP` 量化到分 |
| 时间 | 全库东八区字面量，写库用 `core.timezone.now()` |
| 登录锁定 | 连续失败 5 次锁 15 分钟（`LOGIN_FAIL_LIMIT` / `LOGIN_FAIL_LOCK_MINUTES`），后台与会员同口径 |
| 权限缓存 | 300 秒；改角色或权限后需 `invalidate_user()` 才立即生效 |
